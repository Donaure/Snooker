# 完整接口与规则说明

`SnookerMatchEnv` 在 `player_0`（开球方）与 `player_1` 之间运行一局比赛。
规则：最终同分判平、不重置黑球决胜，单次决策限时 120 秒，超时则判负。
若落后一方需要通过做斯诺克追分，不会提前结束比赛。
每次合法得分后继续击球，并开始新的 120 秒决策预算。
每局默认最多 500 杆（双方合计）；最后一杆结算得分和罚分后，若未正常结束，立即按累计
比分判定，高分方获胜，同分判平。终局原因 `reason` 为 `shot_limit`，胜负和平局分别读取
`winner` 和 `draw`。

## 选手程序限制

比赛决策期间，选手程序不得将当前局面在 MuJoCo 中复制或重建为多个仿真实例，
对不同候选击球进行试打，再根据仿真结果选取最好的一杆。也不得通过反复恢复同一局面，
在单个仿真实例中依次试打来实现同样的搜索。
即使这些试打能够在 120 秒决策预算内完成，也不允许使用这种方式选择击球。

允许选手程序调用课程环境进行出杆可行性检查。该检查只检测球杆是否会碰到其他球，
不模拟球的运动。

## 启动对局

```bash
conda activate pool
python scripts/tools/play_snooker_match.py \
  --player-0 'python scripts/tools/snooker_example_player.py' \
  --player-1 'python scripts/tools/snooker_example_player.py'
```

每位 player 每局使用一个常驻进程，在首次轮到该 player 时启动：

1. player 完成导入库、加载模型，向 stdout 输出一行 `{"op":"ready"}` 并 flush。
2. 裁判开始120s决策计时，将当前状态以一行 JSON 写入 player 的标准输入。
3. player 读取状态，输出击球动作，例如 [angle, speed]。
4. 环境执行这一杆，更新状态，将新状态发给接下来应击球的 player 的同一进程。

`--startup-seconds 300` 设置每位 player 独立的初始化超时，默认 300 秒，不占用回合的 120 秒。


## Python 接口

如果 player 的 Python 脚本需要导入本项目的 `snooker_env` 包，请从仓库根目录使用 `PYTHONPATH=src python 脚本路径` 运行。仅通过 JSON 协议通信、不导入项目代码的 player 程序无需设置。

```python
from snooker_env.snooker_env import SnookerMatchEnv

with SnookerMatchEnv() as env:
    state = env.get_match_state("player_0")
    player, token = state["current_player"], state["turn_id"]
    # 开局白球由环境在 D 区合法位置随机摆放，选手不能修改。
    # 可选：归一化直角坐标击球点，向右为 +u，世界向上为 +v。
    state = env.submit_shot(player, 1.60, 1.2, u=0.2, v=-0.3, turn_id=token)
    # 省略 u/v 时击打水平视角下的正中点（u=v=0）。
```

可用 `SnookerMatchEnv(shot_limit=500)` 设置上限，状态中的 `shot_count` 和
`shot_limit` 分别表示已完成的总杆数和本局上限。
`reset()` 重新开始新局。

角度从世界 +X 向 +Y 逆时针增加，单位为弧度。速度必须为正，表示球杆速度。
可选的 `u, v` 是以球半径为单位的直角坐标击球点，
满足 `u*u + v*v < 1`，默认均为零。沿水平击球方向看向白球时，向右为正 `u`，世界向上为正 `v`。
非有效值会在物理执行前被拒绝。

击球点固定在水平击球方向坐标系中。设球心为 `c`、半径为 `R`，
`h=(cos(angle),sin(angle),0)`、`right=(sin(angle),-cos(angle),0)`，则球面接触点为：

```text
p = c + R * (u * right + v * (0,0,1) - sqrt(1-u*u-v*v) * h)
```

单位圆只是几何输入范围，不保证每个点都可到达或能产生稳定旋转。
不可行的杆路会抛出 `StrokeInfeasibleError`。
大偏移可能使皮头滑动。
MuJoCo 实际积分球杆接触、球间碰撞、库边接触和入袋过程。

状态包含比分、当前与最高单杆得分、当前选手、回合令牌、剩余时间、全部 22 个球的位置和
有效标志、当前合法目标球（Ball On）、彩球与自由球指定、犯规选择、手中球状态、球台尺寸、
点位、袋口，以及上一杆的物理事件和判罚，可 JSON 序列化。`state["action"]` 是击球参数的格式说明。
`state["last_shot"]` 保存上一杆的动作和裁判结果。

特殊操作：

| 方法 | 用途 |
| --- | --- |
| `nominate_colour(player, ball, turn_id=...)` | 红球得分后指定彩球 |
| `nominate_free_ball(player, ball, turn_id=...)` | 获得自由球资格时指定一颗仍在台面上的非目标球；`None` 表示放弃 |
| `place_cue_ball(player, x, y, turn_id=...)` | 手中球时在 D 区摆放或重新摆放白球 |
| `choose_foul(player, choice, turn_id=...)` | 选择 `accept`、`play_again`，或在判定 miss 后选择 `restore` |
| `forfeit(player, turn_id=...)` | 当前选手认输 |

开局白球由环境在 D 区合法位置随机摆放，选手不能修改。白球落袋或被击出台面后，环境提供
空闲的 D 区位置；选手可以在击球前修改。任选彩球阶段（`stage="colour"`）必须先调用
`nominate_colour` 显式指定彩球，未指定时拒绝击球。使用自由球也必须显式指定。
开始摆球、指定球或击球即表示接受犯规后的局面。`accept` 保留剩余决策时间；
要求犯规方重打则给该选手开启一个新的计时回合。

恢复局面时保留双方比分和全部罚分，只恢复击球前的球位、手中球状态和 Ball On 阶段。
若恢复到红球后的彩球阶段，犯规方可以重新选择彩球。要求犯规方重打时不保留自由球资格。

`reset` 或前一杆结束后开放新回合时，决策计时开始。读取状态、指定彩球、摆白球和接受犯规
均不重置计时。即使选手始终不返回，监视计时器也会判定超时。内部杆路规划、物理仿真和
自动裁判的时间不计入选手预算。无效请求会抛出异常，计时继续；仿真失败会恢复击球前局面
和未使用的决策时间。独立选手首次启动时，宿主会在发送任何比赛状态前暂时冻结决策计时，
收到 `ready` 后恢复原有剩余预算，进程启动、导入库、加载模型和预热不占用该预算。
该豁免每位选手每局仅一次，后续回合不重复豁免；选手协议不提供暂停或延时接口。
调用 `close()` 或使用上下文管理器释放计时器。
测试中可以缩短 `turn_seconds`，正式比赛默认值为 120。

## 选手程序需要处理的全部决策情况

`current_player` 表示当前 player；
对手犯规后，当前 player 可能只需选择让对手重打，并不一定要亲自出杆。

### 普通回合与目标球切换

| 情况 | 策略需要处理的行为 |
| --- | --- |
| 开局 | `player_0` 先手，`stage="red"`，`last_shot=None`；`ball_in_hand=False`，白球由环境在 D 区合法位置随机摆放，选手只能选择开球方案，不能修改球位。 |
| 合法得分且未终局 | 同一选手继续，`turn_id` 更新并获得新的决策预算；重新读取球位和目标，规划下一杆。 |
| 合法击球但未得分 | 换对手击球；独立程序等待下次收到状态。 |
| 有球进袋但同杆犯规 | 击球方该杆不得分，对手获得罚分及尚可用的犯规选择。 |
| `stage="red"` | 从 `legal_targets` 中选择红球；合法同杆打进多颗红球可累计得分，随后只有一次任选彩球的机会。 |
| `stage="colour"` | 必须先调用 `nominate_colour` 显式指定一颗彩球，再提交击球；未指定时拒绝击球。 |
| 红彩交替中打完彩球 | 仍有红球时，下一杆目标回到红球；彩球未进、轮到对手回合，目标也是红球 |
| 最后一颗红球合法得分 | 仍有一次任选彩球的机会，之后才进入清彩；若最后红球在犯规中离台，则没有这次彩球机会。 |
| `stage="clearance"` | 按黄、绿、棕、蓝、粉、黑顺序打，使用 `clearance_ball` 和 `legal_targets`；不调用任选彩球接口。 |
| 没有理想进攻路线或被斯诺克 | 仍需在预算内提交一杆，选择防守或解球；没有跳过回合的操作。`snookered_at_current_position` 只描述当前球位，不能据此自行取得自由球资格。 |

每次读取 `balls` 时先筛选 `active=True`，不要对 `position=None` 的球计算距离或瞄准方向。
`legal_targets` 表示当前 Ball On；指定自由球后，还应结合 `nominated_free_ball` 规划首碰，
该自由球不会被追加到 `legal_targets` 中。新回合会清除上一回合的彩球和自由球指定。

### 犯规后的选择、手中球和自由球

`foul_options` 有三种可能，表示此时可选的犯规处理方式：

| `foul_options` | 出现条件 |
| --- | --- |
| `[]` | 没有待处理的犯规选择 |
| `["accept", "play_again"]` | 犯规，未判定为 Foul and a Miss。 |
| `["accept", "play_again", "restore"]` | 犯规，且判定为 Foul and a Miss。 |

| 情况／状态 | 策略需要选择什么 | 操作与后果 |
| --- | --- | --- |
| 可选 `accept` | 是否自己接受当前局面 | `choose_foul("accept")`：接受当前局面，由自己打。 |
| 可选 `play_again` | 是否让犯规方从犯规后的局面继续打 | `choose_foul("play_again")`：保留当前局面，由犯规方继续打；若母球在手中，由犯规方摆球。 |
| 可选 `restore` | 是否恢复犯规前局面让犯规方重打 |  `choose_foul("restore")`；恢复犯规前的局面，由犯规方重打。 |
| `ball_in_hand=True` | 是否调整母球位置以及放在哪里 | `place_cue_ball(x, y)`：母球中心须在 D 区内且不能与其他球重叠。出杆前可重复调整。 |
| `free_ball_available=True` | 是否使用自由球，使用哪颗替代球 | `nominate_free_ball(ball)`：显式指定仍在台面上的非 Ball On 目标球；`None`（JSON 为 `null`）取消指定，也可不指定而直接打真实目标球。 |
| 自己被要求继续或恢复重打 | 针对收到的新状态重新选球、摆球和规划 | 重新指定目标球和选取动作；恢复到任选彩球阶段时可重新选彩球，重打时不保留自由球资格。 |

**先完成犯规选择，再提交摆球或指定操作。** 当前实现中，摆母球、指定彩球、指定自由球
（包括传入 `null`）都会清除待处理的犯规选择，相当于接受局面；直接击球也会接受局面。
一旦这样做，就不能再要求对手继续或恢复重打。

开局白球由环境在 D 区内不与其他球重叠的位置均匀随机摆放，每次 `reset()` 重新抽取，选手不能指定。
手中球出现在母球落袋或离台之后，不是每次犯规都有，也不允许在全台任意摆球。
手中球和自由球可能同时出现，策略应联合考虑摆球位置、替代球和击球路线。
手中球时，环境的自由球资格判断考虑 D 区可摆位置，不能仅凭默认母球位置被挡住就判自由球。

自由球按真实目标球的分值计分，进袋后复位：当红球为目标时，打进替代红球的自由球得 1 分，
接着有一次任选彩球机会；清彩阶段仅打进自由球，真实目标彩球仍需继续打。
同时打进自由球和真实目标彩球时只计一次该彩球分值，清彩顺序按真实目标是否进袋推进。
指定自由球后首碰必须包含该自由球，不能指定后仍只首碰真实目标球。

### 球位变化、终局与运行异常

| 情况 | 策略需要处理的行为 |
| --- | --- |
| 彩球入袋、离台或犯规后复位 | 环境自动摆回彩球，原点被占用时可能使用其他位置；根据返回的 `balls` 重新规划，不自行改动球位。 |
| 红球入袋或离台 | 通常不复位，包括犯规中移除的红球；恢复 miss 前局面时可能重新出现，不能假设 `active` 只会从真变假。 |
| 清彩到最后黑球 | 黑球合法入袋或该杆犯规即按结算后比分结束，最终同分判平；不再请求继续击球或犯规复位。 |
| 达到 `shot_limit` | 先结算最后一杆，再按比分结束；犯规和每次重打都占杆数，复位不退回杆数。策略应把剩余杆数纳入追分或保分判断。 |
| 落后超过台面可得分 | 当前环境不会仅因需要罚分追分而结束；可继续通过防守、做斯诺克争取罚分。 |
| 主动认输 | Python 调用者可用 `forfeit`；独立选手 JSON 协议没有认输操作，不要发送 `{"op":"forfeit"}`。 |
| `terminated=True` | 停止决策，以 `winner`、`draw`、`reason` 读取结果。独立程序也须处理 stdin 结束或宿主关闭进程，不能假设一定收到终局状态。 |
| 决策超时 | 默认 120 秒，摆球、指定、查询和接受犯规均共用预算；为输出和协议往返预留时间，超时直接判负。 |
| 无效规则请求、协议错误或程序退出 | Python 直接调用的无效请求抛异常且计时继续；独立程序的无效规则请求或协议错误会被判负，不能通过试发非法请求探测可用选项。 |
| 不可行出杆或仿真异常 | 环境回滚球位并恢复未用时间；独立程序宿主会收到异常，不会自动得到“犯规”响应或自动重试。 |

### 推荐决策顺序与协议约束

1. 初始化完成后只发送一次 `ready`，随后循环读取状态；若输入结束或比赛已终局则停止。
2. 检查 `current_player`、`turn_id`、`seconds_remaining` 和 `foul_options`。Python 调用者只用
   最新状态的选手和令牌操作，不因同一选手连续得分就复用旧令牌。
3. 若有犯规选择，先比较接受局面、让对手继续和恢复重打。选择后两者时，本次决策立即结束，
   不再输出摆球或击球动作。独立程序不会收到该请求的即时状态响应，下一行输入是下次轮到自己时的状态。
4. 确定自己出杆后，联合规划目标球、可选的 D 区位置、自由球、进攻／防守方案和击球参数。
5. 提交必要的摆球和指定请求，每发一条都 flush 并读取更新状态后再发下一条；用返回状态确认
   指定和剩余时间，不把同一请求反复当成新回合，也不因 `ball_in_hand` 出杆前仍为真而无限重复摆球。
6. 输出一条击球动作并 flush，然后等待下一次输入。合法得分时可能仍是自己，未得分或犯规时
   可能要等待对手；交接和计分由环境执行，策略不要自行切换选手或推进阶段。

`phase="foul_choice"` 表示有待选犯规处理，`phase="shot"` 仍可能需要摆球或指定；
不存在独立的“摆球阶段”或“自由球阶段”，必须同时检查对应字段。
`phase="initializing"` 由宿主管理，握手完成前不会向独立选手发送比赛状态；
`phase="finished"` 表示已终局。每次合法得分继续击球和每次重打都会开启新令牌与新预算，
同一令牌下的击球前请求不会延长预算。

## 独立选手程序

`SnookerProgramPlayer` 为一位选手在一局中维持同一个进程，每次轮到该选手时将 JSON 状态
作为单行写入 stdin，然后读取 stdout。首次发送状态前，选手必须先完成初始化握手：

```python
import json
# 在此导入其余库，加载模型（GPU 操作也应等待完成）。
print(json.dumps({"op": "ready"}), flush=True)
# 然后进入循环，读取 stdin 中的比赛状态并计算动作。
```

初始化阶段不会发送比赛状态；请勿先等待 stdin 再输出 `ready`。旧版选手需增加这一行握手。
初始化日志写入 stderr。`ready` 后发生的延迟导入、模型加载或预热仍计入决策时间。
选手应循环读取状态，输出一行 JSON 并 flush，
出杆后继续等待下一回合；可以在内存中保留本局状态。最简单的选手返回：

```json
[1.5707963267948966, 1.2]
```

如需选择击球点，则返回四个标量：

```json
[1.5707963267948966, 1.2, 0.2, -0.3]
```

此例在固定水平视角下向右偏移 `0.2R`、向下偏移 `0.3R`。
程序协议只接受两个或四个标量。Python 调用者可按位置或关键字传入 `u`、`v`，二者默认均为零。

如需击球前的规则操作，发送一行 JSON 请求、flush stdout，并在下一次请求或最终击球前
读取一行更新后的状态：

```json
{"op": "nominate_colour", "ball": 21}
```

支持的操作包括 `state`、`nominate_colour`（参数 `ball`）、
`nominate_free_ball`（参数 `ball`，可为 `null`）、`place_cue_ball`（参数 `x`、`y`）和
`choose_foul`（参数 `choice`）。要求对手重打会结束非犯规方的当前回合，但保留其进程，
随后由运行器向犯规方的常驻进程发送状态。要求重打后，下一行输入是再次轮到自己时的状态，
不另发当前请求的响应。诊断信息写入 stderr。命令按参数数组执行，不经过 shell。
每行 stdout 协议数据上限为 64 KiB。协议或动作格式错误、程序崩溃会判负；
仿真错误会向宿主传播以便诊断。

初始化单独使用默认 300 秒的截止时间，可用命令行 `--startup-seconds` 或
`SnookerProgramPlayer(command, startup_seconds=300)` 调整。
初始化超时判负，原因是 `player_initialization_timeout`；就绪前退出或握手格式错误按
`player_program_error` 判负。初始化失败也会清理选手进程组。`ready` 只能发送一次，
重复发送不会重置计时。收到就绪后，不完整输出和所有击球前请求共用当前回合的截止时间；
后续各回合仍有独立的 120 秒决策预算。选手进程退出后不会自动重启；下次调用发现退出时判负。
比赛结束（包括超时、
协议错误）、诊断停止或异常退出时，运行器终止双方整个进程组，包括后代进程。
直接使用 `SnookerProgramPlayer` 时，每局为每位选手创建独立实例，用 `with` 或 `finally`
中的 `close()` 确保双方进程被清理。进程内直接调用也受比赛级监视计时器约束，不过环境无法
中断其他线程中的任意代码。
宿主也可先调用 `program.start()` 等待就绪，再创建 `SnookerMatchEnv`，显式在赛前初始化；
`start()` 的初始化失败直接抛出异常，调用者负责处理，成功后 `play_turn()` 复用同一进程。
直接调用 Python 环境方法的选手应在创建环境前完成自身初始化。

## 球、球台与物理资源

球编号 `0` 为白球，`1..15` 为红球，`16..21` 依次为黄、绿、棕、蓝、粉、黑。
红球计 1 分，各彩球分别计 2 至 7 分。

尺寸参考 [WPBSA 2024–25 规则手册的设备章节](https://wpbsa.com/wp-content/uploads/2198_WPBSA-Rulebook-2024-25.pdf)。
库边内侧的有效台面为 3.569 × 1.778 m，球直径为 52.5 mm，开球线距底库 737 mm，
D 区半径为 292 mm，黑球点距顶库 324 mm。
所有球质量均为 140.6 g。橡胶最高点距展示地板 864 mm。
台呢保持在世界坐标 z=1.05 m，地板位于 z=0.229 m。

`models/snooker_scene.xml` 与 `models/snooker_balls.xml` 是由
`scripts/assets/build_snooker_assets.py` 生成的原创程序化资源；共享形状定义位于
`src/snooker_env/snooker_table_assets.py`。球台包含成型橡胶库边、弯曲的角袋和中袋袋角、
石板袋沿与实际开口、缝制皮革袋口、金属袋架、编织网袋、木制围板、装饰线条与八根车制桌腿。
台呢具有细微的程序化织物纹理。场景复用已有许可的球杆外观和
物理皮头、杆身。

台呢和袋角碰撞使用 MuJoCo 原生凸几何块。袋角外观与碰撞分段遵循相同轮廓。球必须进入石板开口并下降到台呢以下
100 mm 才算入袋；只触碰袋角或袋沿不算入袋，球回到台呢高度时会清除待入袋标记。
网袋和袋口五金仅为外观细节，不施加额外捕获力。

Snooker 接触参数位于 `src/snooker_env/snooker_parameters.py`。
滑动、滚动和自旋摩擦分别拟合公开实验，另有球间恢复系数及随速度变化的库边回弹损失。
`SnookerPhysics` 在求解冲量前，通过 MuJoCo 原生分步与约束 API 应用橡胶阻尼曲线。
直接调用 `mujoco.mj_step` 只使用 XML 中的静态参考阻尼；需要完整材料模型的诊断仿真应使用
`SnookerPhysics._step()`。

参见[物理参数、复现命令与局限](snooker_calibration.md)和
[球台资源尺寸与来源](https://github.com/Donaure/Snooker/blob/master/assets/table/snooker/README.md)。

## 规则与裁判范围

每局总杆数默认上限为 500，包含犯规和复位重打；达到上限时先结算该杆，再按比分判胜负，
同分判平。此时不再允许复位。上限可通过 `shot_limit` 或命令行 `--shot-limit` 设置。

引擎处理单杆多颗红球、单颗指定彩球、最后一颗红球后的额外彩球、按顺序清彩、
每杆取最高罚分的 4–7 分犯规处罚、白球落袋和球出台、彩球重置、连续得分、自由球、
重打选择，以及最后黑球进袋或犯规后的终局。任何犯规都会取消击球方该杆得分。
犯规中离台的红球不回台，除非恢复 miss 前的局面；犯规中离台的彩球会重置，清彩阶段也如此。
自由球按 Ball On 的分值计分并重置，不消耗实际红球。清彩阶段仅打入自由球不会清除原彩球；
同时打入自由球和原彩球时，只计算一次该彩球分值。

重置先尝试本球点位，再尝试最高分的可用彩球点，之后沿本球点位的纵向线向顶库方向寻找
最近的不接触位置。该方向无可用位置时再向底库搜索。多颗彩球需要重置时按分值从高到低处理。

仿真与裁判使用以下明确的近似：

- 袋口轮廓为通用程序化模型，并非认证的 WPBSA 模板。台呢、球和正碰库边响应拟合公开测量；
  将橡胶模型用于斜碰和袋角是一项假设。没有拟合台呢绒向、湿度、局部磨损、库边老化和皮头差异。
  该模型不能确定真实球台的进袋概率。
- 固定白球位置的斯诺克判断检查目标球两侧的极限切线路径，不将其他 Ball On 当作斯诺克遮挡。
  手中球资格检查以 5 mm 网格搜索合法 D 区位置，可能漏掉更小的无阻挡窗口。
- 自动 miss 判定搜索直接路径和最多四次理想库边反弹。将球台镜像展开后，以球体切线、
  目标球与障碍球碰撞圆的交点、碰撞圆与库边的交点，以及直库段端点划分角度区间；检查
  区间内部与边界方向，再折回球台逐段验证首碰顺序。
  白球按点处理，其他球的碰撞半径扩大为两倍球半径；先碰任何合法目标球均可，
  同时首碰非法目标球不可行。浮点计算使用微小容差，极端相切情形仍受数值精度限制。
  可反弹的直库段使用球台资产的 `MIDDLE_RUNOUT`、`CORNER_RUNOUT` 尺寸，排除袋口、
  弧形袋角及直库段端点，不把袋口缺口当作完整库边。
  若找到可行路径而首碰失败，则判 miss。该模型不验证速度、旋转、球杆可达性和真实
  库边响应；超过四库或需要弧形袋角反弹的路线不在搜索范围内，未找到不代表物理上无解。
  默认判定仅缓存最近一次结果：键包含未舍入的二维球位、球号、合法目标集合和反弹上限。
  连续复位到相同局面可复用结果；不同局面的判定会替换缓存，分数和高度不参与此二维判定。
  可传入 `route_oracle(positions, targets) -> bool` 替代这一判断。
  当前采用项目给定的可行路径规则，不包含国际规则中的主观尽力或分差例外，也不会自动增加三次 miss 判负。
- 球杆避障以 1 度搜索、0.1 度细化，并采样检查球台扫掠。不可行出杆、未停稳或不稳定的仿真会抛出异常。接触先后顺序在积分步精度上判定。选手接口不提供跳球控制。


## 球杆尺寸与近似

皮头直径为 **9.5 mm**，采用短胶囊的球冠近似，突出杆身前端约 **5 mm**；后半部嵌入前端。
杆身用五段胶囊近似锥度，直径从杆尾的 29 mm 逐段减小至前端的 9.5 mm，所有分段均参与避障检查。

球杆总质量保持 **530 g**，其中皮头为 **0.5 g**；按分段质量计算，重心距杆尾约 **496.5 mm**。
惯量由 MuJoCo 根据各段几何和质量计算。

未模拟皮革形变、真实皮头曲率、巧粉或滑杆极限；
执行器仍逐步指定球杆运动。自动抬杆不改变指定的母球接触点。

验证样例：沿 +Y 方向、杆速 0.6 m/s 时，`u=±0.3` 得到约 `ωz=±9.80 rad/s` 的左右旋转；
`v=+0.3/-0.3` 分别得到约 `ωx=-9.12/+9.59 rad/s`。旋转在皮头最后一次接触时采样。
这些结果验证方向与实现一致性，不代表已实测校准真实球杆的旋转幅值。
